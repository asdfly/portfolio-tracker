# 测试交接评估 - portfolio_tracker

严过关 | 2026-08-05 | 实跑 + 覆盖率数据核验

## 一、实跑结果

环境：项目内 `venv/Scripts/python.exe`（Python 3.10.11 / pytest 9.1.1），依赖齐备。

```
pytest tests/ -q  →  7 failed, 1465 passed, 4 skipped, 268.78s
collect-only      →  1476 collected, 0 收集错误
```

套件能跑通、无导入断裂，这是最大资产。但**当前是红的**。

**这个基线有严格限定词**：它是"在 HUAWEI 这台机器上 1465 passed"，不是"这个套件 1465 passed"。见第五节 P0-3。

失败构成（7 = 5 + 2）：
- `test_d11_version_release::TestReadme` **5 个** —— README 于 8/3 重写后删掉 655 tests / docker / ci / license 等字样，测试未同步。文档漂移，非产品缺陷。
- `test_d5_env_config::TestEnvFileLoading` **2 个** —— 报错为 `OSError: [safe-delete] windows-sandbox-recycle-bin-unavailable`，是本机沙箱拦了 `unlink()`，**属环境产物，非代码缺陷，Linux runner 上会过**。但这不为该测试脱罪：它写删真实 `.env` 的设计缺陷独立成立，见 P0-2。

评估期一度出现第 8 红（`test_d6_root_cleanup`），系我自己的临时脚本 `_qa_cov.py` 触发根目录白名单断言所致，已清理并复跑转绿。**真实本地基线为 7 红，非 8。**

## 二、测试分布

78 文件 / 1413 test 函数 / 1881 断言。命名按**交付批次**而非领域组织：d1-d15（16 文件 218 测试）、p0-p3、tab1-tab15，新人无法从目录判断某功能测在哪。其中约 96 个是 meta 测试（断言 README 内容、Dockerfile 存在、函数行数），测仓库不测产品，上述 5 个失败全出自这类。

## 四、能否作为回归基线

**部分可信，不能直接采信**，三个折扣：

1. **零断言测试 91 个（6.4%）**：test_tab_render.py 全部 25 个形如 `render_tab3()` 直接调用无 assert，test_tab12_tab13.py 13 个同样。tabs 那 70.9% 主要由 MagicMock 冒烟撑起，只证明"不抛异常"，不证明"算得对"。
2. **断言密度 1.33 条/测试**偏薄；全库 `pytest.raises` 仅 2 处、`pytest.approx` 仅 12 处，**异常路径近乎无覆盖**。
3. **弱断言占比高**：isinstance 152 + is not None 99 = 251 条只验类型不验值。

## 五、P0 测试缺陷

**P0-1 测试污染真实生产库（已实测复现）**：conftest.py 仅 63 行 4 fixture，**无 DB 隔离**，9 个测试文件直连真实 DATABASE_PATH。本次跑完 `git status` 显示 `M data/database/portfolio.db`，该 88MB 真实库 mtime 变为运行时刻。跑一次测试改一次生产库，基线不可重复。

**P0-2 测试写删项目根 `.env`（已实测复现）**：`test_d5_env_config.py:95-122` 对 `PROJECT_ROOT/".env"` 执行 write_text 后 unlink，未用 tmp_path。开发者若有真实 .env（SMTP 密码、企微 webhook），跑测试即静默覆盖删除。test_d14_backup.py 有同类行为。

**P0-3 基线依赖本机，换机即失效**：4 个测试文件依赖真实 portfolio.db，其中两处硬编码含用户名的绝对路径 —— `test_d1_margin_research_block.py:9` 的 `DB_PATH = r"C:\Users\HUAWEI\...\portfolio.db"`（第 133/146/156 行真实 connect）、`test_p2_reports_utils.py:63` 的 `EmailReportBuilder(db_path=r"C:\Users\HUAWEI\...")`。它们全绿只因这台机器上该路径恰好成立。且失效方式很隐蔽：实测 `sqlite3.connect()` 对不存在路径**不抛错，静默建一个 0 字节文件**，随后才以 `no such table` 报错，不会干脆地提示"库找不到"。

**P0-4 CI 配置本身注定失败（实测）**：把 ci.yml 的 env 原样搬到本地跑全量，同机同码，唯一变量是环境变量：

```
无 env（本节基线）  →  7 failed, 1465 passed
带 CI env          →  67 failed, 1405 passed
```

A/B/C 对照隔离到单一根因 `DATABASE_PATH: ":memory:"`（ci.yml:28）：test_tab_render.py 在只设该变量时 23 failed/2 passed，只设 EMAIL/WECHAT 时 25 passed，不设时 25 passed。空内存库无任何表，所有读真实数据的测试全部 `pandas.errors.DatabaseError`。**CI 首跑预期红 65-75 个，不是 7 个。**

本地与 CI 的红灯集合**不是包含关系，会换一批**：本地 2 个 test_d5 沙箱红在 CI 会转绿；CI 则新增 `test_d5_env_config.py:60-62 test_database_path_default` 红（它断言 `'portfolio.db' in DATABASE_PATH`，而 CI 给的是 `:memory:`，已在模拟run中实际出现）。所以不能拿本地红灯清单去核对 CI 红灯清单。

另需澄清一个易误判点：portfolio.db 已在 HEAD 被跟踪，push 后 CI checkout **会拿到这份库**。那批测试红**不是因为库缺失，是因为 `:memory:` 把它覆盖了**。只有"撤掉 `:memory:` 且同时把库移出 git"时，才会出现真正的缺库红 —— 届时必须配套 fixture 库。

**P1-1 CI 已两个月未运行且无覆盖率门禁**：`origin/master` 停在 `7cbada1`(2026-06-05)，此后 130 commits / 181 文件 / +24836-12025，其中 32 个测试文件全新、从未在 CI 执行过。ci.yml 无 --cov 无 fail_under，故 .coveragerc 的 fail_under=30 从未生效，且 source=src 与实际范围不一致。CI 为 ubuntu + Python 3.12，本地 Windows + 3.10，双重漂移。"有 CI 保护"是假象。

**P1-2 84MB 二进制入库**：portfolio.db 不在 origin/master 但在 HEAD（commit 24574df），首次 push 会推 84MB 上 GitHub。它同时被 .gitignore 忽略又被 git 跟踪（ignore 对已跟踪文件无效），故每次跑测试都产生一次巨型二进制 diff。

## 六、接手后策略

前两步不做完，不要相信任何绿灯。

1. **先建隔离（阻断级）**：conftest 加 autouse fixture 把 DATABASE_PATH monkeypatch 到 tmp_path 并预建 schema；d5/d14 的真实路径写入改 tmp_path；两处硬编码 `C:\Users\HUAWEI\` 绝对路径改为 PROJECT_ROOT 相对路径。这一步同时解掉 P0-1/2/3/4 —— 有了隔离，ci.yml 的 `:memory:` 才不会满盘皆红。重跑确认 git status 干净。
2. **修红或删红**：5 个 README meta 测试要么同步要么删，零信息量却长期占红灯额度，会训练团队忽略红灯。
3. **重算覆盖率**：现有 coverage.json 作废，隔离后重生成取真实基线。
4. **补核心弱区**：portfolio.py → run_analysis.py → excel_report.py → fund_flow.py，四处合计 1496 语句、平均覆盖不足 15%，均在资金/持仓/出报告主链路。
5. **给零断言冒烟补断言**，至少断言关键 metric 值。
6. **CI 加 `--cov-fail-under`**（锚定真实基线只升不降），统一 Python 3.10。

**结论**：现有套件可当**冒烟基线**（能挡导入断裂与明显崩溃），但完成隔离前**不能当回归基线** —— 会改生产库的套件，其"通过"不可重复，就不构成证据。

## 七、遗留物

已全部清理并复验：`_qa_cov.py` 与残留 `.env` 均已删除，test_d6 复跑 21 passed，`git status` 干净。
