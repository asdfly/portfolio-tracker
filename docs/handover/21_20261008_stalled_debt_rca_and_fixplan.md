## 1. 债务① NAV 恒等式 —— 已闭环，真正该修的是台账

### 1.1 代码事实（当轮）

`src/analysis/nav_engine.py:381`：

```python
"total_units": round(v / unit_nav, 2) if unit_nav else None,
```

这正是 `07_ 问题三` §建议修法里写出的那一行。旧 bug 形态 `round(prev_v, 2)` 在源码中**已不存在**。

### 1.2 数据事实（当轮只读实测）

探针：`audit/probe_stalled_debt_20261008.py`

| 判据 | 命中 | 分母 |
|---|---:|---:|
| `total_units` 非 NULL | **3,493** | 3,493 |
| A）旧 bug 形态：`total_units ≈ 前一日 total_value` | **2** | 3,492 |
| B）正确形态：`total_units × unit_nav ≈ total_value` | **3,493** | 3,493 |

> ⚠️ A 组那 2 行**不是 bug 残留**：B 组是 **3,493/3,493 全命中**，即全表每一行都已满足
> `total_units = total_value / unit_nav` ⇒ 不可能同时存在 `total_units = prev_v` 的错误行。
> 那 2 行是「当日 r≈0 且 unit_nav 恰好使两个表达式数值接近」的**巧合**，不应计入错位统计。

样本（最近 4 行）：

残差恒 < 1 元（`round(2)` 累加所致），恒等式成立。

### 1.3 为什么历史旧行会被自动刷正（关键机制）

`run_analysis.py:1453-1468` 挂在**每日 15:30 无人值守管线**内：

```python
# === P0-2: 重建单位净值账本（TWR 时间加权收益）===
if time.time() > _report_soft_deadline:
    logger.info("[报告保护] 软截止已到, 跳过 NAV 重建(非必需)")
else:
    try:
        from src.analysis.nav_engine import rebuild_portfolio_nav
        _nav_rows = rebuild_portfolio_nav()          # ← 全量重建 3,493 行
    except Exception as e:
        logger.warning(f"单位净值账本重建失败(不影响主流程): {e}")   # ← 异常仅 warning
```

`rebuild_portfolio_nav()`（`nav_engine.py:291`）对 **`portfolio_nav` 全表 `INSERT OR REPLACE`**（`:426-431`）。
⇒ 写入逻辑一旦改对，**下一次日常管线跑起来就会把全历史重刷一遍**，无需人工补操作。
这与「当前 max(date)=2026-10-07 且全表恒等式成立」完全吻合。

另有回归守卫 **`tests/test_total_units_identity.py`** 已就位（专门断言 `total_units == total_value / unit_nav`）。

### 2.4 更正：`12_ §14` 的"入口归属"判断是错的

真正的每天自动重写者有两个，且**作用域不同，必须分开证明**：

| 入口 | 是否每天无人值守 | 作用域 | 证据 |
|---|---|---|---|
| **(a)** `run_analysis.py:1462 → rebuild_portfolio_nav()` | ✅ 是（15:30 管线） | **`portfolio_nav` 全表 3,493 行** `INSERT OR REPLACE`；异常仅 `warning` **不阻断** | `run_analysis.py:1453-1468`；`nav_engine.py:426-431` |

⇒ reconcile 确实每天在写 `fund_flows`，但**它没有动 `portfolio_summary`**。
