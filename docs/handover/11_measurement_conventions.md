## 1. 通用报数规则：分母必须显式声明

**规则**：任何形如「越界占比 / 缺失率 / 差异率 / 一致率」的数字，**必须写成分子 + 分母**，
不允许只写一个百分数。

- 反例（不可接受）：`boll_pctb 越界 5.4%`
- 正例（可接受）：`boll_pctb 越界 1855 行 / 34202 行非空 = 5.4237%`（同处给出 `1855 / 34400 全表 = 5.3924%`）

**原因**：本仓同一张表的「全表行数」与「某列非空行数」在早期年份差异巨大
（`etf_features` 有 4091 行结构性 OHLC 缺失，见 `12_*` §11.1），
两种分母能给出**不同量级**的结论，且差异集中在最需要判读的尾部样本上。

### 1.1 参照量若取自「按 code 截取的窗口」，就必须逐 code 报（或声明取值域）

**规则**：凡判据的**参照量**（基期、分母、窗口首行、上一有效观测）来自
「**按 `code` 截取的窗口**」，该参照量就**随 `code` 变化**。
此时写成一个数不可复现——必须**逐 `code` 报**，或**明确声明其取值域**。

本仓已实测两个同构实例（二者都是「同结论、不同参照量」）：

| 判据 | 参照量 | 随 code 变化的实测取值域 |
|---|---|---|
| Tier2 复制行 `c/n` | 分母 `n` = 该日可比场外标的数 | `n ∈ {6, 11, 12, 13}`（窗口按行数截，各 code 回溯起点不同） |
| 有效基期 `gap` | 基期 `last_real_date` = **窗口首行**（`portfolio_risk.py:504`） | `gap ∈ {0, 15, 30}`（见 §5.2） |

⇒ 报「占比 50%」「gap 超限」而不给参照量，等于隐去了最关键的参差。

### 1.2 对数判据必须写明底数

**规则**：写「对数」时必须声明底数。SQLite 的 `LOG()` 是**十进制**对数，`LN()` 才是自然对数。

**实测（13 只场外基金全快照历史，门槛 `0.20`）**：

| 底数 | 命中边数 | 命中标的数 |
|---|---|---|
| `ln`（自然对数，与 `np.log` / `SPLIT_SPIKE_LOG_RET` 配套） | **6** | **6** |
| `log10`（SQLite `LOG()`） | **0** | **0** |

⇒ 用 `LOG()` 去配自然对数门槛会**整体静默返回空**（不是少几只，是**一只都不命中**），
因为 `log10(x) = ln(x) / 2.3026`：同一门槛在两种底数下相差 **2.3 倍**。
这是「静默失败」而非「报错」——最危险的一类。

⇒ `SPLIT_SPIKE_LOG_RET` 之类门槛必须与 `np.log` / `LN()` 配套；SQL 侧一律显式写 `LN()`。

## 2. `|x| > 1` 越界判据的适用域

### 2.1 判据本身

`|x| > 1` 仅用于判定「该列出现了不该出现的量纲/尺度异常」，**不是**「该列有离群值」的同义词。
它**不**是通用离群检测器。

### 2.2 适用域由「越界占比」判定，不由 min/max 有界性判定

很多列**天然**越界（比值、百分位、z-score），此时 `|x| > 1` 恒真、判据无信息量。
**判别方式**：看该列自身的越界占比，占比高 ⇒ 该列结构性不适用。

### 2.3 阈值 1% 与其「9.3 倍天然空隙」（阈值不敏感的依据）

对 `etf_features` 全表逐列实测（2026-09-16，共 31 个特征列，34,400 行）：

> **适用域**：`etf_features` **全部 34,400 行**（22 只标的，`2012-05-28` ~ `2026-09-14`），
> **包含** 2012–2017 那 4,091 行结构性缺失行（见 `12_*` §11.1）。
> 若把面板收窄到 `date >= '2018-01-02'`（30,309 行），§2.5 的越界计数会整体变小
> （适用 24 列合计 **561 → 412**）。⇒ **引用 §2.5 任一数字前先确认面板范围。**

| 组 | 列数 | 越界占比（分母 = 该列非空行数） |
|---|---|---|
| **不适用**（占比 ≥ 1%） | **7** | 5.4237% ~ 100% |
| **适用**（占比 < 1%） | **24** | 0 ~ **0.5834%**（最大 = `ret_60d`） |

- 适用组上界 **0.5834%**，不适用组下界 **5.4237%**，比值 = **9.30 倍**。
- ⇒ 阈值取 1% 时，它**落在一条宽 9.3 倍的空隙里**，上下各留约 1.7 倍 / 5.4 倍余量。
  **结论对阈值不敏感**：取 0.7%~5% 之间任何值都得到同一个 7 列集合。
- ⚠️ **这个 9.30 只在「分母 = 非空」下成立**。同一批数改用「分母 = 全表 34400」，
  适用组上界 0.5610% / 不适用组下界 5.3924%，比值 = **9.61 倍**。
  ⇒ 引用「9.3 倍空隙」时必须同时说明分母，否则数字不可复现。

### 2.9 ⚠️ 「不可复现」的正确表述（附我的一次实例错误记录）

**错误记录（verify-p1-batch，2026-09-16）**：本文档首版曾在 §2.8 写下
「401 / 456 定义未能回收，**禁止引用**」。**该结论错误**——两数定义良好，即本节 §2.8 的逐案窗口口径，

**错因**：我只在「**全表聚合**」这一维内枚举了 6 组定义，**从未考虑「逐案窗口」这一维**，
却把「我的 6 组定义没产生它」写成了「它没有定义」——**把自己的定义空间当成了全空间**。

**约定 8（新增，由本案例产生）**：

> 「不可复现」只能表述为「**在本轮下述定义空间内不可复现**」，并且**必须同时交出该定义空间**
> （枚举了哪些维、每维取了哪些值）。**不得**升级为「无定义」或「禁止引用」。

正确表述示范：
> 「401 / 456 在『全表聚合 × {单元格, 行并集} × {全表, 收窄面板}』共 6 组定义下均未复现；
> **未覆盖『逐案窗口』这一维**。请定义方补充窗口口径后重测。」

**反向提醒**：本案例同时说明，「口径未声明」的责任**在报数方**——
若 `401 / 456` 初次出现时就带了「26 行 × 32 列 × 起点=案发日」，不会有这一轮返工。

三个 fetcher **都显式**把 `close` 赋给 `adj_close`：

| fetcher | 位置 | 该源 `close` 的真实语义 |
|---|---|---|
| `fetch_etf_ohlcv_akshare`（em） | `:65` | 前复权（qfq） |
| `fetch_etf_ohlcv_sina` | `:100` | **未复权（接口无 adjust 参数）** |
| `fetch_etf_ohlcv_tx` | `:183` | 前复权（qfq） |

⇒ 全表 `adj_close` 与 `close` 逐位相等，**是这个恒等式的产物**，与「数据源有没有复权」无关。

### 3.3 🔴 由此得出的陷阱（本节存在的真正理由）

「`adj_close == close` ⇒ 该列不含复权」这个推论**只在 em/tx 段成立**。

一旦 `sina` 入链，`adj_close` 会变成「**未复权价被贴上复权标签**」，
而列相等性**依然逐位成立** ⇒ §3.2 的检测手段**结构性失效**，没有任何报警。

⇒ **不得**把「`adj_close == close`」当作「复权口径正确」的验收证据。
复权口径的正确性只能由 **source 白名单**（em/tx）证明，不能由列相等性证明。

### 3.4 实测（2026-09-16，生产库只读 `mode=ro`）

- `etf_price_history` 共 **31,515** 行，日期 `2018-01-02` ~ `2026-09-15`。
- `typeof(adj_close)` 与 `typeof(close)` **全部为 `real`**（无 TEXT 伪装导致的假相等）。
- `hex(adj_close) = hex(close)`（**IEEE754 位级**比对）：**31,515 / 31,515 = 100.0000%**，不等 **0** 行。
- 按 source：`akshare_fund_etf_hist_em` 24,497 行（全等）、`akshare_stock_zh_a_hist_tx_qfq` 7,018 行（全等）。
- **`akshare_fund_etf_hist_sina` 段 = 0 行** ⇒ 该休眠路径从未落过库。

## 5. 复制行与有效基期的观测分布

### 5.1 Tier2 复制行判据的 `c/n` 分布（**双峰，50% 线不承重**）

**适用域**（缺一不可，漏任一项数字不可复现）：

- **篮子**：`portfolio_snapshots` 场外篮子（`is_otc_fund` **13 只**，`config/settings.py:368`）
- **窗口**：每 `code` `get_price_history(code, 60)` = **`LIMIT 60` 行**，
  **不是 60 个日历日**。多数 code 历史不足 60 行 ⇒ 退化为全历史（实测 `001194` 33 行、`027293` 8 行）
- **key**：`(current_price, round(market_value, 2))`（`portfolio_risk.py::_replica_key`）
- **判据**：`n >= COPY_BREADTH_MIN_N(3)` 且 `c*2 >= n` ⇒ VOID（`portfolio_risk.py:221` / `:223`）
- **观测区间**：可比日 `2026-02-28 ~ 2026-09-15`，其中 `n >= 3` 者共 **48 天**

逐日 `n / c / ratio` 实测分布：

| 分组 | 天数 | `ratio = c/n` |
|---|---|---|
| **触发 VOID** | **10** | **全部 `= 1.0000`** |
| 未触发、`c > 0` | **4** | `0.2500`（`09-09`，`3/12`）、`0.0833`（`08-05`、`09-01`，各 `1/12`）、`0.0769`（`08-21`，`1/13`） |
| 未触发、`c == 0` | **34** | `0.0000` |

- **非 VOID 上界 `0.2500`、VOID 下界 `1.0000`** ⇒ 阈值取 `(0.25, 1.00]` 内任何值，48 天裁决**完全相同**。
- 判据在观测样本上等价于「**全篮同值 vs 非全篮同值**」的二值判断；
  **不存在中间态被裁决的案例（实测一个都没有）。**
- VOID 日实测 = `06-17 ~ 06-29`（9 天，`n=11, c=11`）+ `09-15`（`n=12, c=12`）。
- **稳健性**：改用**全历史**（不截 60 行）重算，三种分组计数**不变**（`34 / 10 / 4`）。

**两条推论**：

1. `COPY_BREADTH_MIN_RATIO` 是「**非承重常量**」，**不只是「未被消费」**——
   代码 `:223` 硬编码 `c*2 < n`、常量只进日志（`:226`）。
   **即使真的消费它，观测样本上的行为也完全一样** ⇒ 风险说明按「非承重」措辞，**不按「无影响」**。
2. 保留 `0.5` 的价值**不在历史分辨力，而在对未来中间态的防御**——
   中间区间现在空着，但**空得没有理由保证将来还空**。

> 📌 本节是 §1.1「参照量逐 code 变」的实例：分母 `n` 在本样本内取 `{11, 12, 13}`。
> 只写「占比 50%」看不出它是「分母 12 里的 6」还是「分母 6 里的 3」。
>

### 5.2 有效基期 `gap` 逐 code 分布（同一事件日，三种参照量）

`gap` 的基期 = **窗口首行**（`portfolio_risk.py:504` `last_real_date = dates[0]`），
且 `:520-521` 在跨期分支里**推进基期** ⇒ 同一个 `2026-06-30`，各 `code` 的 `gap` 并不相同。

**实测（窗口 = 每 `code` `LIMIT 60` 行，判据顺序走生产实现）**：

| 窗口首行 | 只数 | 标的 | `06-30` 的 `gap` | 处置机制 |
|---|---|---|---|---|
| `2026-06-15` | 5 | `001323` `001407` `001437` `002152` `519770` | **15** | `gap > 12` ⇒ 跨期 |
| `2026-01-31` | 6 | `001765` `007994` `008269` `100032` `166301` `880013` | **30** | `gap > 12` ⇒ 跨期 |
| `2026-06-30` | 1 | `027293` | — | **窗口首行即基期，无收益位置** |
| `2026-07-31` | 1 | `001194` | — | `06-30` **不在窗口内** |

> ⚠️ **纠正一处流传数**：曾报 head=`2026-01-31` 组 `gap = 150`（= `01-31 → 06-30` 的自然日差）。
> 实测为 **30**。原因：`02-28 / 03-31 / 04-30 / 05-31` 都是**真实观测**，
> 跨期分支会**推进基期**；到 `06-30` 时基期已是 `05-31`（`05-31 → 06-30 = 30`）。
> **取 `dates[0]` 而不推进基期，才会得到 150。**

**同一个 `06-15` 的两种身份，决定了 15 还是 30**：

- 在 head=`06-15` 组的窗口里，`06-15` 是**窗口首行** ⇒ `:504` 无条件取它当基期 ⇒ `06-15 → 06-30 =` **15**；
- 在 head=`01-31` 组的窗口里，`06-15` 是**内部行**，且它是 `06-15~06-29` 复制段的**段首**，
  被 Tier1 整段 void（**含段首**，`COPY_RUN_MIN_LEN = 5`）⇒ 基期停在 `05-31` ⇒ **30**。

⇒ **「窗口首行」与「内部行」的处置不同**（前者无条件当基期，后者可能被判据作废），
这才是 `gap` 逐 code 变化的真正机制——**不是**「各 code 数据不同」。

**机制清点（是三项，不是「两病因」）**：

| 机制 | 只数 |
|---|---|
| `gap > MAX_SINGLE_SESSION_GAP_DAYS(12)` ⇒ 跨期 | **11** |
| 窗口首行即基期（无收益位置） | **1** |
| 事件日不在窗口内 | **1** |
| `gap <= 0`（同日重复采集） | **0** |

> ⚠️ `gap <= 0` **实测 0 例**，与 `portfolio_risk.py:515-516` 代码注释自述（「当前生产库实测 0 例」）一致。
> **不得**把 `027293` 的 `06-30` 归为 `gap <= 0`——它是**窗口首行当基期**，两者机制不同。
