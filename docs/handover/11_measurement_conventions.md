## 1. 通用报数规则：分母必须显式声明

**规则**：任何形如「越界占比 / 缺失率 / 差异率 / 一致率」的数字，**必须写成分子 + 分母**，
不允许只写一个百分数。

- 反例（不可接受）：`boll_pctb 越界 5.4%`
- 正例（可接受）：`boll_pctb 越界 1855 行 / 34202 行非空 = 5.4237%`（同处给出 `1855 / 34400 全表 = 5.3924%`）

**原因**：本仓同一张表的「全表行数」与「某列非空行数」在早期年份差异巨大
（`etf_features` 有 4091 行结构性 OHLC 缺失，见 `12_*` §11.1），
两种分母能给出**不同量级**的结论，且差异集中在最需要判读的尾部样本上。

## 2. `|x| > 1` 越界判据的适用域

### 2.1 判据本身

`|x| > 1` 仅用于判定「该列出现了不该出现的量纲/尺度异常」，**不是**「该列有离群值」的同义词。
它**不**是通用离群检测器。

### 2.2 适用域由「越界占比」判定，不由 min/max 有界性判定

很多列**天然**越界（比值、百分位、z-score），此时 `|x| > 1` 恒真、判据无信息量。
**判别方式**：看该列自身的越界占比，占比高 ⇒ 该列结构性不适用。

### 2.3 阈值 1% 与其「9.3 倍天然空隙」（阈值不敏感的依据）

对 `etf_features` 全表逐列实测（2026-09-16，共 31 个特征列，34,400 行）：

> **适用域**：`etf_features` **全部 34,400 行**（22 只标的，`2012-05-28` ~ `2026-09-14`），
> **包含** 2012–2017 那 4,091 行结构性缺失行（见 `12_*` §11.1）。
> 若把面板收窄到 `date >= '2018-01-02'`（30,309 行），§2.5 的越界计数会整体变小
> （适用 24 列合计 **561 → 412**）。⇒ **引用 §2.5 任一数字前先确认面板范围。**

| 组 | 列数 | 越界占比（分母 = 该列非空行数） |
|---|---|---|
| **不适用**（占比 ≥ 1%） | **7** | 5.4237% ~ 100% |
| **适用**（占比 < 1%） | **24** | 0 ~ **0.5834%**（最大 = `ret_60d`） |

- 适用组上界 **0.5834%**，不适用组下界 **5.4237%**，比值 = **9.30 倍**。
- ⇒ 阈值取 1% 时，它**落在一条宽 9.3 倍的空隙里**，上下各留约 1.7 倍 / 5.4 倍余量。
  **结论对阈值不敏感**：取 0.7%~5% 之间任何值都得到同一个 7 列集合。
- ⚠️ **这个 9.30 只在「分母 = 非空」下成立**。同一批数改用「分母 = 全表 34400」，
  适用组上界 0.5610% / 不适用组下界 5.3924%，比值 = **9.61 倍**。
  ⇒ 引用「9.3 倍空隙」时必须同时说明分母，否则数字不可复现。

### 2.6 聚合值：口径是**三维**的，缺一维数字就不可比

| 维 | 取值 | 说明 |
|---|---|---|
| **① 计数单位** | 单元格 ／ 行并集 | 同一行可多列越界，两者「不是同一个量」 |
| **② 面板范围** | 全表 34,400 ／ 收窄 `>=2018-01-02` 30,309 | 差 4,091 行结构性缺失（`12_*` §11.1） |
| **③ 统计窗口** | 全表聚合 ／ **逐案窗口** | 见 §2.8；窗口起点与行数是**必带口径** |

| 计数单位 | 全表 · 全表聚合 | 收窄 · 全表聚合 | **全表 · 5 个折算窗口** |

| 年 | 2012 | 2013 | 2014 | **2015** | 2016 | 2017 | 2018 | 2019 | 2020 | **2021** | **2022** | 2023 | **2024** | **2025** | 2026 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 越界 | 0 | 0 | 0 | **149** | 0 | 0 | 0 | 0 | 0 | **64** | **110** | 0 | **197** | **41** | 0 |

- **15 个年份里 10 年正好为 0**，全部越界集中在 **5 个年份**（2015 / 2021 / 2022 / 2024 / 2025），合计 561。
- 对照 #86 已定性的 5 例真污染
  （`510500`@2015-04-15 / `512010`@2021-06-28 / `512100`@2022-09-05 / `159300`@2024-06-25 / `516160`@2024-09-18）：
  其年份集合 **{2015, 2021, 2022, 2024}** 是上表非零年份的**真子集**。
- ⚠️ 上表**多出 2025（41 行）**，而 2025 年**没有**任何已定性事件与之对应。
  ⇒ 这是**新增待查项**，不得表述为「年份集合与已定性事件一致」。

  孤立年份的簇状越界才是嫌疑对象；跨年份均匀分布的越界更像该列的常态。
- 📌 本节是「年」粒度的粗看；**更锐的量化见 §2.8**（5 个窗口 = 0.3779% 的行，容纳 **71.48%** 的越界单元格）。

### 2.9 ⚠️ 「不可复现」的正确表述（附我的一次实物错误记录）

**错误记录（verify-p1-batch，2026-09-16）**：本文档首版曾在 §2.8 写下
「401 / 456 定义未能回收，**禁止引用**」。**该结论错误**——两数定义良好，即本节 §2.8 的逐案窗口口径，
已被逐项复现（`401`、`456`、差值 `55` 三项全部命中）。

**错因**：我只在「**全表聚合**」这一维内枚举了 6 组定义，**从未考虑「逐案窗口」这一维**，
却把「我的 6 组定义没产生它」写成了「它没有定义」——**把自己的定义空间当成了全空间**。

**约定 8（新增，由本案例产生）**：

> 「不可复现」只能表述为「**在本轮下述定义空间内不可复现**」，并且**必须同时交出该定义空间**
> （枚举了哪些维、每维取了哪些值）。**不得**升级为「无定义」或「禁止引用」。

正确表述示范：
> 「401 / 456 在『全表聚合 × {单元格, 行并集} × {全表, 收窄面板}』共 6 组定义下均未复现；
> **未覆盖『逐案窗口』这一维**。请定义方补充窗口口径后重测。」

**反向提醒**：本案例同时说明，「口径未声明」的责任**在报数方**——
若 `401 / 456` 初次出现时就带了「26 行 × 32 列 × 起点=案发日」，不会有这一轮返工。

## 3. `adj_close` 语义与 sina 休眠路径登记

### 3.1 登记条目（裁定：**(a) 维持现状**）

> **`fetch_etf_ohlcv_sina` 的 `adj_close` 为休眠路径（dormant path）——维持现状，不修改、不收紧、不删除。**

| 项 | 内容 |
|---|---|
| 符号 | `src/analysis/predictor/price_history.py::fetch_etf_ohlcv_sina`（定义 `:76`） |
| 休眠值 | `:100` `out["adj_close"] = out["close"]` |
| 源标记 | `:20` `SOURCE_SINA = "akshare_fund_etf_hist_sina"` |
| 注册面 | `:206` `FETCHERS = {"em": …, "tx": …, "sina": …}`，`:209` 同行注释「未复权源，禁用」 |
| **不在默认链路** | `:223` `backfill_etf_price_history(..., sources: Iterable[str] = ("em", "tx"), ...)` |
| 文档串禁令 | `:82-85`「⚠️ 禁止用于填充行情表……该函数仅为兼容/人工排查保留，**不得**放回默认 sources」 |
| 同上（补数入口） | `:236-238`「⚠️ 默认 sources=("em","tx") 均为前复权(qfq)源。**不得**把 "sina" 放回默认链路」 |
| 守卫测试 1 | `tests/test_predictor_price_history_tx.py:136` `test_default_sources_are_qfq_only` |
| 守卫测试 2 | `tests/test_predictor_price_history_tx.py:147` `test_backfill_default_never_writes_unadjusted_rows` |
| 守卫实测 | 2026-09-16 实跑上述 2 例：**2 passed, 7 deselected in 2.15s** |

**维持现状的理由**：该路径当前**不可达**（默认链路 em→tx；且被 2 条守卫测试钉死），
修改它需要重跑守卫测试与全量回归，而收益为零。**休眠 + 双层守卫 + 本节登记** 已足够。
（裁定来源：team-lead；登记落笔：verify-p1-batch。）

### 3.2 为什么必须登记：`adj_close ≡ close` 是**写入方恒等式**，不是数据性质

三个 fetcher **都显式**把 `close` 赋给 `adj_close`：

| fetcher | 位置 | 该源 `close` 的真实语义 |
|---|---|---|
| `fetch_etf_ohlcv_akshare`（em） | `:65` | 前复权（qfq） |
| `fetch_etf_ohlcv_sina` | `:100` | **未复权（接口无 adjust 参数）** |
| `fetch_etf_ohlcv_tx` | `:183` | 前复权（qfq） |

⇒ 全表 `adj_close` 与 `close` 逐位相等，**是这个恒等式的产物**，与「数据源有没有复权」无关。

### 3.3 🔴 由此得出的陷阱（本节存在的真正理由）

「`adj_close == close` ⇒ 该列不含复权」这个推论**只在 em/tx 段成立**。

一旦 `sina` 入链，`adj_close` 会变成「**未复权价被贴上复权标签**」，
而列相等性**依然逐位成立** ⇒ §3.2 的检测手段**结构性失效**，没有任何报警。

⇒ **不得**把「`adj_close == close`」当作「复权口径正确」的验收证据。
复权口径的正确性只能由 **source 白名单**（em/tx）证明，不能由列相等性证明。

### 3.4 实测（2026-09-16，生产库只读 `mode=ro`）

- `etf_price_history` 共 **31,515** 行，日期 `2018-01-02` ~ `2026-09-15`。
- `typeof(adj_close)` 与 `typeof(close)` **全部为 `real`**（无 TEXT 伪装导致的假相等）。
- `hex(adj_close) = hex(close)`（**IEEE754 位级**比对）：**31,515 / 31,515 = 100.0000%**，不等 **0** 行。
- 按 source：`akshare_fund_etf_hist_em` 24,497 行（全等）、`akshare_stock_zh_a_hist_tx_qfq` 7,018 行（全等）。
- **`akshare_fund_etf_hist_sina` 段 = 0 行** ⇒ 该休眠路径从未落过库。

> ⚠️ 曾有一组 `99.7907% / 99.9098%` 被当作「`adj_close` 与 `close` 的一致率」流转。
> 实测该两数**不是**本表的一致率（本表为 100.0000%），而是 §2.4 中 `rsi_14` 越界占比的两种分母写法。
> 引用时勿再互换。

### 3.5 若将来必须改（未授权，仅记录约束）

休眠路径若要收紧，**唯一**可行方向是在 `FETCHERS` 层拒绝 `sina`（或让 `backfill_etf_price_history`
对非白名单源直接抛错），**不能**靠改 `adj_close` 的赋值——见 §3.3，那样做是静默的。

| 5 | **报数必须声明适用域与口径，含分母** | 见本文件 §1、§2.3：同一批数换分母会得出 9.30 vs 9.61 |
| 6 | **数字必须来自真实执行**，不得由心算/换算得出 | 曾出现「99.88%」系心算换算、从未执行 |
| 6a | （约定 6 的两步式）**先怀疑非执行产物，但第二步必须排除数据漂移** | 「反解不出 ⇒ 非执行产物」这个单步签名会把「合法执行 + 两次快照同症状」误杀；两次快照同症状的另一个病因是数据漂移，须先核全表行数未变才能下结论 |
| 7 | **状态类断言必须当轮实测**（候选，待裁定） | 「某守卫存在 ⇒ 该路径不可达」曾被当作结论直接使用；正确做法是当轮跑一次该守卫并附计数（本文件 §3.1 守卫实测即此条的正面样本） |
| 8 | **「不可复现」必须限定在已枚举的定义空间内，并交出该定义空间**；不得升级为「无定义」/「禁止引用」 | verify-p1-batch 把 401/456 判为「定义未能回收、禁止引用」，实际只是自己漏了「逐案窗口」这一维；两数定义良好且已逐项复现（见 §2.9） |

**附注（约定 6a 的由来）**：同一症状可由**两个不同病因**产生——① 该输出根本不是本次执行的产物；
② 是合法执行，但两次快照恰好同症状。**只做第一步会误杀②**。两步都必须做完才能落结论。
