## 二、逐项诊断

### 【P0】收益率二次除权（最严重，已实证）
- **根因**：`data_loader.load_calendar_data()` 第 308 行已执行 `df["daily_return"] = df["daily_return"] / 100`，即传入 tab4 的 `daily_return` **已是小数**。
- 但 tab4 又在三处对小数再除以 100：
  - L59 `ret_sum=("daily_return", lambda x: (1 + x / 100).prod() - 1)`（年度概览"月收益率"列）
  - L82-83 `yr_daily = (year_df["daily_return"] / 100)`（全年收益率）
  - L168 `m_daily = (month_df["daily_return"] / 100)`（月度视图"月收益率"指标）
- L257 日历格 tooltip 直接 `{ret:+.2f}%`，而 `ret` 是小数（未 ×100），显示成 `0.01%` 样式。
- **实证（生产库）**：
  - 2026-08 真实月收益率 **+5.769%**，前端显示 **+0.0583%**（≈99× 缩水）
  - 2026-09 真实月收益率 **−1.342%**，前端显示 **−0.0131%**（≈103× 缩水）
- **反向对照（正确处）**：热图走 `compute_monthly_returns()`（内部 ÷100 一次 → 小数 → ×100 显示），日收益明细表 L284 用 `ret*100`——这两处是对的。说明口径不一致是 tab4 局部引入的。

### 【P1】颜色语义违反 A 股惯例
- 当前：盈利/正收益 = 绿 `#22c55e`，亏损/负收益 = 红 `#ef4444`（L117-118、L135-136、L152-156、L212-213、L312 热图 colorscale）。
- 问题：A 股与中国主流理财 App（支付宝/理财通/天天基金）均为 **涨红跌绿**；且 tab1 已用 `delta_color="inverse"` 落实该惯例。Tab4 与之矛盾，属于内部不一致。
- 决策点（需你确认）：默认建议统一为 **涨红跌绿**；若你更习惯"绿=赚"的全球范式，则保持现状并仅在文档标注。本方案按"对齐 A 股惯例"给改动。

### 【P1-2】事件日历"假个性化" + 逻辑 bug
- L421 标题与 L479/L503/L527 文案称"自动检测持仓中的关键事件日期"，但代码**完全未读取持仓/分红除息数据**，仅是硬编码的 A 股通用披露窗口规则。
- 逻辑缺陷：
  - L461 `if current_year == current_year:` 恒真（遗留死判断）。
  - L462-467 仅处理 `s_m == 当前月` 或 `s_m > 当前月`，**跨年披露期（年报 1/1–4/30）在 5–12 月永不显示**。
  - L437 年报窗口 (1,1)–(4,30) 与 L434 一季报 (4,1)–(4,30) 在 4 月重叠双显。
  - L532 `if 12 <= current_month <= 12 or 1 <= current_month <= 1:` 等价于 `if 当前月 in (1,12)`，写法冗余。
- 优化方向：要么**老实改名为"市场关键日期"**（通用日历，去掉"持仓"措辞），要么**真正接入数据**（从持仓 ETF 的 `etf_dividend`/公告表或个股研究拉取真实分红除息日、财报披露日），后者价值更高但需数据层配合。

### 【P2】性能 / 死代码
- L339 `_render_annual_trend` 内部又 `load_calendar_data()`，忽略入参 `all_cal` → 重复全量查库。应直接用入参。
- L161 `month_df = year_df[year_df["month"] == sel_month]` 计算后未使用（函数返回 `year_df`），属死代码；可删或改为返回 `month_df`。

### 【P2】显示细节
- L249-254 同格金额同时用"万"（`pnl/10000`）与"k"（`pnl/1000`）两种单位，建议统一为"万/亿"中文单位。
- L219 `cal-pnl-zero: #484f58` 压在 `.cal-trading #161b22` 上对比度过低，零收益日几乎看不清；建议改用 `#6e7681` 或加浅描边。
- L358-382 年化走势把"累计收益率"（可能几十 %~上百 %）与"年化收益率"（个位数 %）放双轴，年化线被压成贴底平线，易误读为"无波动"。建议：保留双轴但加 y2 轴说明，或改为单轴展示累计 + 旁注 CAGR 数值。
- L91-107 年度概览用 `st.columns([1,5])` 逐月行渲染，每行的 5 列 flex 在窄屏会挤压；L222-271 7 列日历网格同理。建议给容器加 `overflow-x:auto` 或最小宽度。

### 【P3】文案
- L293 热图 tooltip 写"展示 12 个月的月度收益"，实际 `compute_monthly_returns` 还含"年累计"列与"月均"汇总行（多年×月）。建议改为"各年度分月收益热力图"。

## 三、优化方案（分阶段）

### 阶段 0 — 修 P0 正确性（必做，影响所有收益率数字）
统一口径：tab4 内 `daily_return` 已是小数，**删除所有多余的 `/100`**，并在需要"百分比字符串"处用 `*100`。
- L59：`lambda x: (1 + x).prod() - 1`
- L82：`yr_daily = year_df["daily_return"].dropna()`
- L168：`m_daily = month_df["daily_return"].dropna()`
- L257：`title="...({ret*100:+.2f}%)"`
- 配套单测：对 `load_calendar_data()` 输出断言 `daily_return` 为小数量级（如典型日值在 ±0.1 内），并断言月度概览某月收益率 ≈ 直接 `(1+dec).prod()-1`。
- QA 门：用本文"实证"段的三个月数据回放，确认 UI 显示与库一致（误差 < 1e-6）。

### 阶段 1 — P1 一致性与事件日历
- **颜色对齐（默认方案）**：将盈利/正收益色由 `#22c55e` 改为红 `#ef4444`、亏损/负收益由 `#ef4444` 改为绿 `#22c55e`，**仅限本 Tab 的 P&L 语义**（日历格、年度概览、热图 colorscale 翻转）。热图 colorscale 改为 `[[0,"#22c55e"],[0.5,"#0d1117"],[1,"#ef4444"]]`。
  - ⚠️ 决策项：是否接受"涨红跌绿"？还是保留"绿=赚"？
- **事件日历**：
  - 方案 A（轻量）：去掉"持仓"措辞，改名"市场关键日期"，并修正逻辑 bug（删恒真判断、支持跨年披露期、消除年报/一季报重叠、精简换仓判断）。
  - 方案 B（数据化，推荐长期）：接入真实数据——从持仓 ETF 分红表/个股研究拉取**实际除息日、财报披露日**，与通用日历合并展示，真正实现"持仓相关事件"。需在 `data_loader` 新增 `load_portfolio_events()`。

### 阶段 2 — P2 工程整洁与显示打磨
- L339 去掉重复 `load_calendar_data()`，改用入参 `all_cal`。
- L161 删除死代码（或返回 `month_df` 复用）。
- 金额单位统一为中文"万/亿"（L249-254）。
- 零收益日对比度（L219 改 `#6e7681` + 浅描边）。
- 年化走势图双轴加明确标注或改单轴 + CAGR 旁注（L358-382）。
- 年度概览 / 日历网格加 `overflow-x:auto` 与最小宽度，提升窄屏（移动端）可用性（L91-107、L222-271）。
- 热图 tooltip 文案修正（L293）。

### 阶段 3 — 可选增强（非必须）
- 日历格当前只显示金额，可叠加"日收益率%"小字，hover 已有 tooltip 足够，按需。
- 年度概览"月收益率"列可加迷你 sparkline（当月每日收益走势），提升信息密度。
- 事件日历与 tab14 市场事件去重/合并，避免两 Tab 重复"事件"叙事。
