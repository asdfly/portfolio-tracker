# 自动化采集任务完善方案

> 版本: v1.0 | 设计日期: 2026-08-05 | 适用项目: portfolio_tracker
> 现状依据: `run_analysis.py`、`src/data_sources/*`、`setup_scheduler.ps1`、8/4-8/5 数据真实性排查复盘

---

## 0. 结论先行

当前采集链路**结构没问题**（单入口 `run_analysis.py`、stage 级 try/except、DB 自动备份、数据质量巡检都已有），但在**四个维度上脆**：

1. **会挂死** — AKShare 裸调无进程级超时，一卡就是几小时，靠 Windows 任务计划的 1h 硬杀兜底，但杀掉前无任何产出与告警。
2. **会静默失真** — 源返回上一交易日数据 / 空数据时被直接落库并标成目标日期（8/4 净值被重标成 8/5 即是此坑）。
3. **缺降级** — 主源（东方财富）在本环境被代理墙挡、债券 ETF（511380）被 `fund_etf_spot_em` 漏掉，均无备用源兜底，结果静默缺失。
4. **缺编排** — 两融等易空数据没有重试/补采闭环；Windows 任务计划与 WorkBuddy 自动化存在 15:10 双触发风险。

方案目标：**零挂死、真数据、能降级、可观测、可回填**。下面按"底座 → 闸门 → 降级 → 调度 → 观测"五层设计，并给出分阶段落地路径与验收标准。

## 2. 设计目标（量化）

- **零挂死**：任意外部调用硬超时 ≤ 30s（可配），整任务墙钟 ≤ 50min（低于调度器 1h 限位）。
- **真实性**：带日期序列数据的"返回最大日期 == 目标日期"校验率 100%；不符项进入 `data_quality_issues`，绝不覆盖。
- **降级覆盖率**：持仓 ETF 行情覆盖率 ≥ 99%（缺失项必告警，不静默）。
- **可观测**：每次运行产出结构化 `run_report_<date>.json`；挂死恢复 / 源全挂 / stale 超阈值 三类事件主动推送。
- **幂等回填**：补采可任意重入，不重复、不破坏既有正确数据。

## 3. 方案设计

### A. 统一采集底座 `src/data_sources/collect_core.py`（治 D1/D2）

**硬超时原语（Windows 兼容）**：AKShare 可能卡死在底层网络/C 调用，信号（SIGALRM 仅 Unix）无效，必须用**子进程 + 队列**保证可杀：

```python
import multiprocessing as mp

def run_with_hard_timeout(func, *args, timeout: float = 30, **kwargs):
    """跨平台硬超时：超时不返回则 kill 子进程，父进程绝不卡死。"""
    ctx = mp.get_context("spawn")
    q: "mp.Queue" = ctx.Queue(maxsize=1)
    p = ctx.Process(target=_worker, args=(q, func, args, kwargs), daemon=True)
    p.start()
    p.join(timeout)
    if p.is_alive():
        p.kill(); p.join()                       # 硬杀，确保释放
        raise CollectTimeout(f"{func.__name__} 超时 {timeout}s")
    if not q.empty():
        ok, val, err = q.get()
        if ok: return val
        raise CollectError(str(err))
    raise CollectError("子进程无返回")

def _worker(q, func, args, kwargs):
    try:
        q.put((True, func(*args, **kwargs), None))
    except Exception as e:                       # 含 AKShare 内部异常
        q.put((False, None, repr(e)))
```

**重试退避**：`retry(max=3, backoff=2, jitter=0.3)`，网络类异常（ProxyError/ConnectionError/Timeout）才重试，数据类异常（空表/字段缺失）直接降级。

**降级链注册表**：每个数据项声明 source 优先级，例：
```
ETF_SPOT = [em_spot, sina_hist_realtime, local_prev_trading_day_cache]
FUND_FLOW_ETF = [push2his, em_spot_batch, sina_kline_estimate]
MARGIN = [sse_detail, sse_detail_retry_next_window]
```
`collect_core.collect(item, target_date)` 依次尝试，命中即返回并打 `meta.source` 标记。

### B. 数据真实性闸门（治 D5）

- 每个采集函数返回 `(df, meta)`，`meta = {data_date, source, latency_ms, is_stale, coverage}`。
- **落库前断言**（在 `save_to_db` 上游拦截）：
  - 序列型（净值/资金流/K线）：`meta.data_date == target_date` 否则写入 `data_quality_issues`（`kind=stale_date, want, got`）并**不覆盖**。
  - 快照型（当日 ETF 行情）：校验 `meta.coverage >= 0.99`（持仓 ETF 覆盖率），缺失 code 走降级链；仍缺失记 `missing_code` 告警。
- `data_quality_issues` 表：`(date, table, code, kind, want, got, created_at)`，`UNIQUE(date, table, code, kind)`。

### C. 多源降级实现（治 D3/D4/D6）

- **债券/特殊 ETF（511380 等）**：`fund_etf_spot_em` 无 → `ak.fund_etf_hist_sina(symbol='sh'+code)` 取真实 OHLC 组装行（已验证可用），`iopv` 字段明确标注为"新浪收盘价代理"，`pct` 列留 NULL 诚实标记。写进 `etf_fundamental.py` 的 `fetch_etf_spot_batch` 降级分支。
- **资金流**：push2his 被墙 → 批量 `fund_etf_spot_em` 已做；再加新浪历史 K 线估算兜底（已有 `backfill_etf_fund_flow_from_kline`）。
- **两融**：`fetch_margin_data` 空 → 进 `retry_next_window` 队列，由补采窗口/自动化在 16:30、次日 09:30 重试（见 D 节）。

### D. 调度编排改进（治 D6/D7）

- **统一为单一真调度器**：保留 Windows 任务计划为唯一生产触发器；WorkBuddy 自动化改为"巡检/补采"角色，**取消 15:10 与任务计划重叠的触发**，避免双跑（D7）。
- **主采集窗口**：交易日 15:10（收盘后数据较齐）。
- **补采窗口**：16:30 对当日 `data_quality_issues` 中 `stale_date/missing_code` 项二次补采；两融增加次日 09:30 重试（替代当前的 one-time 手工自动化，改为条件触发：仅当当日两融为空时触发）。
- **全局看门狗**：`run_analysis.py` 启动即起 `threading.Timer(50min)`，到点若主流程未结束则记 `execution_logs` 告警并 `sys.exit(1)`（不再无限挂，D1 兜底）。

### E. 可观测性（治 D1 兜底 + 主动性）

- 每次运行结束写 `data/reports/run_report_<date>.json`：
  ```json
  { "date":"2026-08-05", "duration_s":232, "stages":{...},
    "sources":[{"name":"ETF_SPOT","ok":21,"fail":0,"timeout":0,"source_used":"em_spot"},
               {"name":"MARGIN","ok":0,"fail":1,"source_used":"sse_detail"}],
    "data_quality_issues":[...], "dq_score":92, "alerts":[...] }
  ```
- 三类事件主动推送（需配 `config/notification.json`）：挂死恢复、源全挂、stale 超阈值。
- 日志已轮转（10MB×5），保留。

### F. 健壮性细节（治 D8）

- `run_analysis.bat` 改为调用项目 `venv` 的 Python（`%PROJECT_DIR%venv\Scripts\python.exe`），消除系统 Python 3.10 漂移。
- DB 备份（`scripts/backup_db.py`）保留，7 天保留策略保留。
- 降级写入一律 `INSERT OR REPLACE` + 日期校验，不破坏既有正确数据。

## 5. 验收标准（EARS 格式）

- **AC-01** While 任意外部采集调用执行超过 30s，系统**必须**杀掉子进程并返回超时异常，主流程**必须**继续后续 stage。
- **AC-02** If 采集返回的序列数据最大日期不等于目标日期，系统**必须**将其记入 `data_quality_issues` 且**必须不**覆盖该日期已有正确数据。
- **AC-03** When 持仓 ETF 在 `fund_etf_spot_em` 中缺失（如 511380），系统**应该**自动降级至新浪历史接口补全。
- **AC-04** While 两融数据采集返回空，系统**必须**将其加入补采队列并在次日 09:30 前重试。
- **AC-05** When 每次运行结束，系统**必须**生成 `run_report_<date>.json` 含各源成功率与缺失项清单。
- **AC-06** If Windows 任务计划与 WorkBuddy 自动化均配置 15:10 触发，系统**必须**只保留单一生产触发器，避免重复运行。

## 6. 风险与权衡

- **硬超时杀进程**可能丢失该次部分结果，但保证整体可恢复——优于整任务挂死。P1 后挂死从"小时级"降为"秒级+告警"。
- **新浪兜底**的 `iopv` 实为收盘价代理，需在字段/报告注明，避免与真实 IOPV 混淆（已在 P3 诚实标记）。
- **降级链顺序**需按本环境实测调整（当前 EM 墙挡、新浪可用），配置化以便切换。
